## 1. "Is our system just: take data by user → process → show results?"

**Yes. Exactly that. And you must say so out loud, because it is the honest
architecture and it is defensible.**

```
USER INPUT              PROCESS                        OUTPUT
─────────────           ──────────────────────        ─────────────────────
N, P, K, pH      ──┐                                 Urea / DAP / MOP bags
(from the lab        │                                 + PKR cost of each
 recommendation       ├──▶ 4 calculation services      + radar chart vs
 report)              │    • sfri.service              target range
                     │    • planner.service      ──▶  + cost breakdown, PKR
District + acres  ────┤    • climate.service            + water, litres
Soil type           ──┤    • simulator.service         + irrigations
Crop + month         │                                 + yield, profit, ROI
Budget              ──┘                                 + break-even price
                     │                                 + source of each figure
                     └──▶ SFRI Guide-V · FAO-56 ·      + what-if comparison
                          PCPA · PAU · NFDC · climate      (slider, % change)
```

### What this is called, and why that is a strength

It is a **deterministic calculation engine with a user interface**. Not AI. Not
machine learning. Not a prediction model. There is **no model file, no training,
no dataset, no GPU, and no inference** anywhere in the repository — the proposal
already states this twice ("hold no machine-learning model of any kind").

**Why that is your strongest position, not your weakest:**

| Property of your design | Why a panelist likes it |
|------------------------|------------------------|
| No trained model | Nothing to hallucinate. The same soil reading always gives the same answer. |
| Formulas come from **Government of Punjab** and **FAO** | You did not invent the agronomy; you implemented it correctly. |
| The method is validated against a **different agency's published figure** | Proof of correctness that does not depend on your own test suite alone. |
| Every output cites its source | Auditable by a third party. This is a rare and respected property. |
| Four **pure functions** | `same input → same output`, no database, no clock. Unit-testable by definition. |

### The exact sentence to say when asked "so is it just a calculator?"

> "Functionally, yes — and that is deliberate. The agronomic formulas are
> published and fixed, so I did not invent them and I do not claim to. The
> computer science is turning four published methods into a **correct,
> validated, fully local, authenticated** service: four pure calculation
> functions, a token-protected API where no farmer can read another's data,
> validation at every input boundary, and a test suite that proves the
> arithmetic against a published government figure. A calculator you can trust
> in a village with no signal is a harder thing to build than a calculator
> with internet access — and it is the thing the farmer is missing."

**Never say** "AI", "machine learning", "model", "trained", "smart", "predicts".
You will be asked *"so where is the AI in it?"* — answer: **"There isn't any,
and the proposal says so. It was a deliberate scope decision; a trained model
would have needed a dataset, a GPU and a paid server, and none of that is
needed to solve the three problems."** That answer wins. Hedging loses.

**Slide 11 — The one calculation that decides the project** ⟳ (your most important slide)

**LEFT — the method as implemented**

```
INPUT   Soil test report: N, P, K (ppm or kg/ha), pH, soil type, acres
   │
1 │ CONVERT   1 acre-foot of soil = 1,000,000 kg  ⇒  1 ppm = 1 kg/acre
   │
2 │ RANK      Poor / Medium / Adequate against the SFRI band for this soil type
   │
3 │ SELECT    Crop requirement from the SFRI Guide-V table for that band
   │
4 │ SUBTRACT  nutrient needed = crop requirement − the farmer's soil test value
   │
5 │ CONVERT   kg nutrient → bags   (Urea 46% N   → 23 kg N per 50 kg bag)
                                (DAP  46% P₂O₅ → 23 kg P₂O₅ per bag)
                                (MOP  60% K₂O  → 30 kg K₂O per bag)
   │
6 │ CEIL      bags/acre × acres = total bags, rounded UP
   │
   │   ⚠ ZERO bags returned when a nutrient is already above target
   │
OUTPUT  Urea bags · DAP bags · MOP bags · PKR cost · radar chart
```
