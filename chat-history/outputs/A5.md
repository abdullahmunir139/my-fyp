## 5. Three decisions I made that you should know about

### 5.1 Problem 3 is written as future work, not as solved

The 4 problems have 16 factors between them. The scorecard in the Scope section
says plainly:

| Problem | Factors | Solved | Partly | **Not solved** |
|---|---|---|---|---|
| P1 uninformed decisions | 4 | 3 | 1 | 0 |
| P2 financial planning | 5 | 4 | 1 | 0 |
| P3 disease diagnosis | 3 | 0 | 0 | **3 → future work** |
| P4 hardware dependency | 4 | 4 | 0 | 0 |
| **Total** | **16** | **11** | **2** | **3** |

**Do not change this.** A supervisor reads the problem statement before the scope.
If the proposal claims a problem you removed a module to solve, the first
question in the defence will be "show me". Losing one problem honestly is much
better than losing the whole proposal on a contradiction.

### 5.2 The name has no "AI" in it

`AgriPulse`, not `AgriPulse AI`. There is no trained model in the repo. A name
that promises AI invites the question "where is your model?" and there isn't one.
If a supervisor asks why, the answer is: *the strongest module implements a
government formula — it did not need to be invented.*

### 5.3 Annexure B — "What Is NOT Claimed"

Six things the system does not do, written down. This looks like weakness and it
is the opposite: it is the section that makes the other 500 lines believable. It
also stops a defence question from being a surprise.
