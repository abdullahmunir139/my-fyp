# c003 — AgriPulse Proposal Rewritten In Student Voice

## What was done

Rewrote the FYP proposal for **AgriPulse** so it reads as a student
project proving a skill rather than a startup pitching an investor. The
previous revision was defensible but had accumulated the vocabulary of a
product launch — an outcome-and-margin register, a "what is NOT claimed"
disclaimer appendix, a deployment section about how a farmer would reach
a locally run app, and offline operation framed as a limitation to be
excused rather than a property of the system.

The teacher's locked PDF was extracted and compared against the working
`.md` before any edit. That comparison established that none of the
startup framing came from the teacher-supplied content: the teacher's own
version already carries exactly three problem bullets, already frames
offline as a positive aim ("must run on one laptop with the router
switched off"), and already contains no deployment section and no
future-work section. All of that framing had been introduced by the
previous revision. This task removed the added layer, which restored the
supervisor's framing rather than substituting a new one.

Removed: the Deployment and Use section in full; Appendix B (twelve rows
of "we do not claim" disclaimers); The Whole-App Rule section, which was
written as a defence ("works with no internet is a promise, zero
dependencies is a false claim, only the first one is defensible"); the
frontmatter status callout announcing the work has not started; the
confessional note in the Tools section about a previous draft's false
"zero dependencies" claim; the Problem Statement's meta-commentary about
how the document would be judged; two risk rows that existed only to
pre-empt examiner objections; the "we have not overclaimed" remark; and
all forward-looking "future work" and "future plans" language.

Reframed rather than deleted: offline operation is now stated as a plain
architectural property in the Tools section — local `mongod`, local JSON
assets, assets served locally, no account and no subscription — with no
defensive scaffolding. The same technical claim, without the apology. The
evidence table was reduced from three categories to two (published figure,
calculated) because the third existed only to defend against an
overclaiming charge. The crop-sourcing rule and the cotton-is-validation-
reference-only distinction were kept intact, as they are the document's
strongest defences and cost no credibility.

One substantive gap was closed: the previous revision argued that offline
operation "is treated as a requirement" without ever naming the computer
science. It now states the actual engineering — four calculation services,
a token-authenticated API, input validation at every boundary, and a test
suite that proves the arithmetic against an official published figure.

A conflict between the locked scope of record (`A4.md`, which requires
disease diagnosis to be stated as future work) and this task (which bans
future-work framing) was resolved by removing the disease problem
entirely: it is not claimed as solved, and it is not promised as future
work. Verified against the teacher's template `.docx` that the mandated
section order is intact, and against the Q8 content-types that aim (5),
objectives (6), scope (1 paragraph + 6 points, no sub-headings) and the two
requirement lists (12 each, plain numbering) are unchanged. No student
personal data was invented.

Only `deliverables/proposal/proposal.md` was edited. No `.pdf`, no `.odt`,
no other deliverable, and no sibling repository.
